# Famochat

A private messenger for family and close friends, built with Next.js for Vercel. Turso stores accounts, sessions, relationships, location-sharing preferences, and messages. Cloudinary stores images, videos, voice notes, and documents.

## Local setup

Requires Node.js 22.13 or newer.

1. Install dependencies:

   ```bash
   npm install
   ```

2. Copy `.env.example` to `.env.local` and add your Turso and Cloudinary credentials.

3. Start the app:

   ```bash
   npm run dev
   ```

The database tables and indexes are created automatically on the first authenticated request. `db/schema.ts` is also kept as the Drizzle schema for future migration generation.

## Turso

Create a database and token, then set:

```dotenv
TURSO_DATABASE_URL=libsql://...
TURSO_AUTH_TOKEN=...
```

For this early-stage app, schema initialization is idempotent and happens at runtime. Before making destructive or data-transforming schema changes, generate and review a migration instead:

```bash
npm run db:generate
```

## Cloudinary

Create a Cloudinary product environment and set:

```dotenv
CLOUDINARY_CLOUD_NAME=...
CLOUDINARY_API_KEY=...
CLOUDINARY_API_SECRET=...
```

Uploads use a short-lived signature generated by the server. The browser uploads directly to Cloudinary, and only the returned asset URL and public ID are stored in Turso. The API secret is never sent to the browser.

## Deploy to Vercel

1. Push this folder to a Git repository and import it in Vercel, or run `vercel` from the project root.
2. Add all five variables from `.env.example` to Vercel for Production and Preview.
3. Keep the detected framework as Next.js and the build command as `npm run build`.
4. Deploy, create the first account, and send a small image to verify Turso and Cloudinary together.

Vercel should use the same Turso database for deployments that need to share accounts. Use a separate Turso database and Cloudinary folder strategy if Preview data must stay isolated from Production.

## Security notes

- Passwords are derived with scrypt and per-user salts on the server.
- Sessions use random tokens stored in `HttpOnly`, `SameSite=Lax` cookies; only token hashes are stored in Turso.
- Every relationship, contact, and message mutation checks the signed-in user on the server.
- Cloudinary upload signatures are only issued to signed-in users and expire according to Cloudinary's signed-upload rules.
- Messages are protected in transit but are not yet end-to-end encrypted at the application layer.
- Shared live context uses browser geolocation, Open-Meteo current weather, and BigDataCloud reverse geocoding. Battery percentage appears only in browsers that expose the Battery Status API; unsupported browsers show it as unavailable.
- A relationship cannot be deleted by either person while parental control is active in either direction.
